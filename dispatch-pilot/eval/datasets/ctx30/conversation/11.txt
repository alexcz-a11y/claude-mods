@@ user

@@ assistant tools=Read*5,Grep*3,Bash mark=E09
原因找到了，是输入法的组合输入没处理，而且同样的写法有三处。

**发票搜索**：`web/src/hooks/useInvoiceSearch.ts`

```ts
export function useInvoiceSearch() {
  const [keyword, setKeyword] = useState('')
  const query = useQuery({
    queryKey: ['invoices', 'search', keyword],
    queryFn: () => api.get('/v1/invoices', { params: { q: keyword } }),
    enabled: keyword.length > 0,
  })
  return { keyword, setKeyword, ...query }
}
```

搜索框是 `<input value={keyword} onChange={(e) => setKeyword(e.target.value)} />`。用拼音输入法打“北京”的时候，组合过程中输入框的值会依次变成 `b`、`be`、`bei`、`bei j`、`bei ji`……每一次 `onChange` 都改 `keyword`，每次都发一个请求、列表换一次结果，最后选中“北京”才是真正的关键词。打一个词会触发五六次请求，结果陆续回来，列表就一直在闪；返回顺序乱的时候，最后显示的甚至可能是 `bei ji` 的结果。

英文没问题，因为没有组合输入，而且英文的每个中间状态本来就是合法的前缀。

**同样的写法还有两处**（看提交记录是照着发票搜索复制的）：
- `web/src/components/CustomerPicker.tsx`：开票时选客户的下拉搜索；
- `web/src/components/ProductSearch.tsx`：添加明细行时搜商品。

`CustomerPicker` 有 300 毫秒的防抖，闪得轻一点，但组合过程中停顿超过 300 毫秒还是会发出拼音的请求；`ProductSearch` 没有防抖。

**修法**：组合输入期间（`compositionstart` 到 `compositionend`）不更新查询用的关键词，组合结束时用最终的值更新；再统一加 250 毫秒的防抖。三处都要改，最好抽一个共用的 hook，比如：

```ts
const { inputProps, value } = useImeSafeInput({ debounceMs: 250 })
// <input {...inputProps} />，value 是组合结束、防抖之后的值
```

测试可以用 Testing Library 的 `fireEvent.compositionStart` / `compositionEnd` 模拟输入法。
