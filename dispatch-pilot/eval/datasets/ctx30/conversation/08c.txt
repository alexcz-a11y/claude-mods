%% X1-5 商户设置的缓存什么时候失效（只是解释）
@@ user
问一下：商户改了设置（比如付款条款），api 多久能生效？有商户说改完以后新开的发票还是旧的条款。

@@ assistant tools=Read*3,Grep*3
最多 10 分钟，大部分情况下是立刻生效，但有一种情况会等满 10 分钟。

**缓存怎么做的**：`api/internal/merchant/settings.go`

```go
func (s *Service) Settings(ctx context.Context, merchantID int64) (Settings, error) {
    if v, ok := s.local.Get(merchantID); ok { // 进程内缓存，30 秒
        return v, nil
    }
    if v, err := s.redisGet(ctx, merchantID); err == nil { // Redis，10 分钟
        s.local.Set(merchantID, v)
        return v, nil
    }
    v, err := s.store.GetMerchantSettings(ctx, merchantID)
    ...
}
```

两层缓存：每个 api 副本自己有一个 30 秒的进程内缓存，下面是 Redis 里 10 分钟的缓存（就是之前看到的 `ms:` 前缀）。

**更新的时候**：`UpdateSettings` 写完数据库以后会删掉 Redis 里的 key，所以 Redis 这一层是立刻失效的。但是进程内缓存删不掉别的副本的，所以其他 5 个副本最多还会用 30 秒的旧值。

**为什么会等 10 分钟**：后台的“付款条款”不是走 `UpdateSettings` 改的，而是一个单独的接口 `PUT /v1/merchant/payment-terms`（`api/internal/merchant/terms.go`），它直接更新数据库，**没有删 Redis 的 key**。所以改付款条款以后，Redis 里的旧值要等 10 分钟过期。这个商户遇到的应该就是这个。

修起来很简单：`terms.go` 里写完数据库以后调一下 `s.invalidate(ctx, merchantID)`，和 `UpdateSettings` 一样。要我改吗？

@@ user
