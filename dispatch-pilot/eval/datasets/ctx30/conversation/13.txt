**数据库**

`invoices.memo` 现在是 `varchar(200)`。在 PostgreSQL 里，`varchar(n)` 改成 `text` 是二进制兼容的类型转换：只改系统表里的列定义，**不重写表、不重建索引**，只需要一瞬间的 ACCESS EXCLUSIVE 锁。`invoices` 虽然有 3100 万行，这个 ALTER 也是毫秒级的。我在本地造了 500 万行的表试了一下：

```
ledgerly_dev=# \timing on
ledgerly_dev=# ALTER TABLE invoices ALTER COLUMN memo TYPE text;
ALTER TABLE
Time: 6.412 ms
```

`memo` 上没有索引，也没有视图依赖它（查了 `pg_depend`）。

迁移文件 `migrations/202610150905_invoices_memo_text.sql`：

```sql
-- +goose Up
ALTER TABLE invoices ALTER COLUMN memo TYPE text;
-- +goose Down
ALTER TABLE invoices ALTER COLUMN memo TYPE varchar(200);
```

回滚那一步要注意：如果已经有人写了超过 200 字的备注，改回 `varchar(200)` 会失败。我在 Down 上面加了注释说明，真要回滚得先截断。为了防止那一瞬间的锁等太久（如果正好有长事务在读 `invoices`，ALTER 会排队，后面的查询又排在 ALTER 后面），迁移开头加了 `SET lock_timeout = '3s';`，拿不到锁就失败，下次再跑，不会把表堵住。

- `api/openapi.yaml`：`memo` 的 `maxLength` 改成 5000；
