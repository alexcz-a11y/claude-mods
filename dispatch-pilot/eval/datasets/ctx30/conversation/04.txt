%% D3 e2e 偶发失败（已修）
@@ user
e2e 里 `web/e2e/invoice-create.spec.ts` 这周挂了三次，重跑又过，你看看。

@@ assistant tools=Read*3,Bash*5,Edit*2
找到两个原因，都已经改了。

**原因 1：点完保存就断言 toast**

```ts
await page.getByRole('button', { name: '保存' }).click()
await expect(page.getByText('发票已保存')).toBeVisible()
```

toast 是 `POST /v1/invoices` 返回之后才弹的。CI 上偶尔接口慢一点（e2e 用的是 docker 里的 api 和数据库，机器忙时 p99 能到 4 秒），而 `toBeVisible` 的默认超时是 5 秒，加上页面上其他请求，就会偶尔超时。

改成先等接口返回再断言：

```ts
const saved = page.waitForResponse((r) => r.url().endsWith('/v1/invoices') && r.request().method() === 'POST')
await page.getByRole('button', { name: '保存' }).click()
expect((await saved).status()).toBe(201)
await expect(page.getByText('发票已保存')).toBeVisible()
```

**原因 2：开票日期默认值取的是 `new Date()`**

用例里断言开票日期输入框的值等于 `format(new Date(), 'yyyy-MM-dd')`，但页面里的默认值用的是商户时区（种子数据里是 `Asia/Shanghai`），CI 机器是 UTC。UTC 16:00 到 24:00 之间跑，两边差一天，用例就挂。这周挂的三次里有两次正好是北京时间凌晨。

改成在用例开头固定时钟：

```ts
await page.clock.setFixedTime(new Date('2026-10-14T03:00:00Z'))
```

断言里的期望值也写成固定的 `2026-10-14`。

**验证**

```
$ pnpm exec playwright test e2e/invoice-create.spec.ts --repeat-each 30
Running 30 tests using 4 workers
  30 passed (2.1m)
```

又把 `TZ=UTC` 和 `TZ=Asia/Shanghai` 各跑了 10 遍，都通过。改动只在这一个 spec 文件里。

```

    11.20s 37.33% 37.33%     18.30s 61.00%  github.com/jung-kurt/gofpdf.(*utf8FontFile).parseTables
```

61% 的时间在解析 TTF 字体：每张发票都 `AddUTF8Font` 两次，每次都把 6 MB 的文件重新读一遍、重新解析字形表。本地机器快，这部分被掩盖了；限了 CPU 以后就是主要开销。

**改法**（PR #829）：
1. `api/internal/invoice/pdf/fonts.go` 新增一个包级的字体缓存：进程启动后第一次用到时用 `sync.Once` 把两个 TTF 读进内存，之后每张发票用 `AddUTF8FontFromBytes` 从内存里的字节加载，不再读文件；
2. gofpdf 内部对同一份字节还是会解析字形表，所以又加了一层：渲染时只在第一页之前加载一次字体，同一个 zip 里的多张发票共用一个 `fontSet`，靠 `pdf.SetFontLoader` 把解析结果复用起来；
3. 发票模板（`templates/invoice/standard.hbs` 编译后的结构）原来每张都重新解析，现在也缓存在包级变量里。

**效果**：
| 场景 | 改之前 | 改之后 |
|---|---|---|
| 本地 200 张 | 41.7s | 12.9s |
| staging（生产同等限额）300 张 | 131s | 58s |
| staging 500 张 | 超时 | 97s |

单张的平均渲染时间从 0.43 秒降到 0.19 秒。按这个数字，线上 500 张应该能在 120 秒内完成。

`go test ./api/internal/invoice/pdf/... ./api/internal/export/...` 全部通过；我另外比对了改前改后同一张发票渲染出的 PDF，用 `pdftotext` 转成文字逐行比较，内容一致。
