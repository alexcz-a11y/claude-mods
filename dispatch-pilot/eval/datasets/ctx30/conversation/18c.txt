# 第一周上手

欢迎加入！这份文档帮你在第一周里把环境跑起来、认识代码、提出第一个 PR。看不懂的地方随时在 #dev 里问，没有人会觉得问题太简单。

## 我们在做什么

Ledgerly 是给小企业用的开票和收款工具。商户在我们的后台创建客户、开发票、发给客户；客户通过发票上的链接付款；钱到账以后，我们按商户的设置定期打款给商户。另外，商户可以通过 API 和 webhook 把 Ledgerly 接进他们自己的系统。

现在有大约 2.5 万个付费商户，大部分在中国大陆，也有一部分在欧洲和澳洲。

## 仓库里有什么

这是一个单仓库（monorepo），主要的目录：

| 目录 | 是什么 | 语言 |
|---|---|---|
| `api/` | 后端 HTTP 服务，后台和开放 API 都在这里 | Go |
| `worker/` | 后台任务：发邮件和短信、逾期提醒、导出、webhook 投递 | Go |
| `web/` | 商户后台的前端 | TypeScript + React |
| `templates/` | 发票的 PDF 和邮件模板 | Handlebars |
| `migrations/` | 数据库迁移 | SQL（goose） |
| `deploy/` | 部署：Helm chart、Terraform、监控告警 | YAML、HCL |
| `docs/` | 内部文档：方案、运维手册、约定 | Markdown |
| `docs-site/` | 对外的帮助中心和开发者文档 | MDX（Docusaurus） |

生产环境跑在 Kubernetes 上，主要有三个服务：`api`、`worker`，以及专门负责给商户打款的 `payout-worker`。数据库是 PostgreSQL 15，缓存是 Redis。

## 第一天：把环境跑起来

需要先装好：Go 1.22、Node 20 和 pnpm、Docker Desktop、`make`。

1. 克隆仓库，在根目录运行 `make dev`。第一次会拉镜像，大约需要两三分钟。
2. 它会启动本地的 PostgreSQL（5433 端口）和 Redis，执行迁移，加载种子数据，然后同时启动 api（8080）、worker 和前端（5173）。
3. 打开 http://localhost:5173 ，用种子数据里的测试账号登录（账号写在 `docs/dev-accounts.md`）。
4. 跑一遍测试确认环境没问题：后端 `go test ./...`（大约 1 分钟），前端 `pnpm -C web vitest run`。

如果 `make dev` 报错，先看 README 的“常见问题”，大部分是端口被占用或者 Docker 没启动。

## 改代码的流程

1. 从 `main` 拉一个分支，名字随意，建议 `feat/...`、`fix/...`。
2. 改代码，加测试。我们不要求覆盖率，但改了逻辑就要有测试能证明它是对的。
3. 本地跑过 `make test` 和 `make lint`。
4. 提 PR，描述里写清楚“改了什么、为什么、怎么验证的”。PR 模板里有这三项。
5. 至少一个人 approve、CI 全绿以后，由你自己合并。
6. 合进 `main` 不会直接上线。我们大约每周发布一次，由负责发布的人按发布清单打 tag。

几个约定：
- 提交信息用中文或英文都可以，但一个 PR 里统一；
- 不要在 PR 里顺手改不相关的东西，再小也单独提；
- 涉及钱（收款、退款、打款）和数据库结构的改动，PR 里要 @ 对应的负责人，不要只找一个人看完就合。

## 第一周做什么

- **第 1 天**：环境跑起来，在后台里自己走一遍“建客户 → 开发票 → 发送 → 付款”的完整流程（种子数据里有测试用的付款渠道，不会真的扣钱）。
- **第 2 天**：读 `docs/` 下的架构说明 `architecture.md` 和值班手册 `ops/oncall.md`，不用全记住，知道有什么就行。
- **第 3 到 5 天**：在 issue 列表里找一个带 `good first issue` 标签的问题，做完提 PR。做的过程中遇到任何问题，找你的导师（入职邮件里写了是谁）。
- **周五**：和你的导师聊 30 分钟，说说这一周哪里卡住了、文档哪里没写清楚，我们会据此改进这份文档。

第二周开始会安排你跟着值班的同事一起值一次班，只看不处理。
