# 校准用例集的官方要求（STANDARD）

dispatch-pilot 校准（设计第 8 节，计划 `docs/superpowers/plans/2026-11-19-dispatch-pilot-calibration.md`）里的出题、参考答案、分组、比较措辞、定门槛、查稳定性和发真实请求之前的同意，都照这张表核对。后面的任务和用例的审查按编号（S1、S2……）引用。

- 取回日期是 2026-11-18（本机时间，PST；UTC 是 2026-11-19）。每一条引文都出自这一天取回的页面，和页面上的文字逐字相同；页面源文件里折行的地方按一个空格算。
- 版本。Nace 官方 skill 取自 `nace-ai/drex-agent-skills` 的 `main`，它的 `plugin.json` 写的是 `0.8.0`，里面有 `drex-for-harness` 和 `drexify` 两个 skill。TypeSafe 官方 skill 取自 `typesafe-ai/skills` 的 `main`，和本机的 `typesafe:typesafe-ai` 0.6.2 逐字相同。Nace 的 models 页（https://console.nace.ai/docs/drex/reference/models ，渲染后）写着 “`drex-latest` is an alias. It currently points to `drex-max-v1.1`.”，表里 `drex-max-v1.1` 是每百万输入 token $0.03，输出不计费，和计划里预算的换算一致。TypeSafe 的 models 页写 `jev-latest` 指向 `jev-1.14.0`。
- 读过的页面。Nace：guides 下的 questions、reading-answers、drex-max、errors-and-retries、state，reference 下的 models、pricing，integrations 下的 promptfoo、langfuse、postgres，以及两个 skill 的全文；文档索引里其余的 Drex 指南和集成页按关键词查过。TypeSafe：官方 skill，primitives 和它下面的 noul、score、choice，confidence、models、model-jaggedness、how-to-build 各页，cookbook 里的 skill_suggestion、consistency_choice、llm_guardrails、basic_memory、autoresearch_feature_discovery、verify_llm_outputs、twitch_chat_filter、classifying_rag_passages，以及 evals.typesafe.ai 首页；其余的 primitives、patterns 和 cookbook 页按关键词查过。只读文档，没有向任何一家的决策接口发请求。
- 最后一列。「Task N Step M」是校准计划的任务和步骤；「全局约束」和「R-……」是计划开头的 Global Constraints 和「跑之前定死的判定规则」。「修订 A1」到「修订 A12」是计划末尾「修订」一节的条目（2026-11-19，对照这张表之后加的），和计划上文不一致时以它为准。写「没有」的，是计划里没有哪一步满足这一条；列了步骤又在后面说缺什么或哪里不改的，是只满足了一部分。
- 「要求」一列开头的粗体字是这一条管哪件事。审查用例时对照「出题」「参考答案」「分组」三组；改措辞、定门槛、查稳定性和发请求之前，对照各自的那一组。
- 两家的话都是建议，不是接口的硬性规定。TypeSafe 的 skill 这样说自己：“None of it is absolute.”

## 和设计 3.4 节不一致的地方

1. **用例数量，Nace 不是完全没有说法。** 3.4 节写「Nace 文档对用例数量、类别比例、标注方法没有说法」。Nace 的文档页确实没有。但同一个官方仓库、同一个插件里的另一个 skill `drexify`（3.4 节只读了 `drex-for-harness`）有一句：“Keep live evaluation small, tens of labeled examples per site, and say how many billable calls ran.”（全句见 S20）。计划每类 15 例，其中调 10 例、留 5 例，在 tens 的下沿。这句话的另外两个要求（报出计费的请求数；调过措辞或门槛的分数要写明，或者留一部分只算分）计划已经满足。例数要不要加，由 controller 和用户定。
   - 决定：例数不加。每类 15 例是用户定的；处在 tens 的下沿这一点照实写进校准记录（修订 A11）。
2. **一句引文的语境不对。** 3.4 节把 “try a score question on a few samples before you rely on it.” 当作 Nace 对 Score 题要先在样例上试的说法。页面（https://console.nace.ai/docs/integrations/langfuse.md ）上整句是 “This wasn't run through Langfuse itself, so try a score question on a few samples before you rely on it.”，说的是经 Langfuse 的适配器发 Score 题要带 `X-Nace-Legend: object` 头，这条路 Nace 自己没有实测过；不是在说 Score 的档位说明。「Score 的说明改写后换一批输入验证」只有 TypeSafe 一家的依据（S10）。不改门槛和流程。
   - 决定：设计 3.4 节在 Task 16 更正（修订 A11）。
3. **拼错的模型名。** 3.4 节在 Nace skill 那一段写「拼错或退役的 `drex-` id 会被别的版本回答，不报错」。skill 今天仍这么写，但文档今天写的是另一回事：退役的 id 和别名转给现行版本，其余的值报错。models 页（https://console.nace.ai/docs/drex/reference/models.md ）：“Any other value returns `422 invalid_request_error`”；migrate-from-typesafe 页（https://console.nace.ai/docs/drex/guides/migrate-from-typesafe.md ）说这样做是 “so a half-migrated client fails on the first call instead of silently using the wrong model.” 核对回答的 `model` 仍然需要（S39），因为退役的 id 和别名确实会由别的版本回答。不改门槛和流程。
   - 决定：设计 3.4 节在 Task 16 更正（修订 A11）。
